# Strudel 集成许可决策

核查日期：2026-10-02。冻结 PRD 不变。

## 建议

若要接入本应用内置播放与动态可视化，建议将整个集成应用以 **AGPL-3.0-or-later** 发布，而不是只给播放适配器加许可证。上线时提供与运行版本对应的完整源代码入口，保留上游版权和许可声明、修改记录及依赖许可证。不能将 iframe 或动态加载视为当然免除许可义务的方案。

这是待仓库权利人确认的发布方案；当前没有修改整个仓库的许可证，也没有安装或分发 Strudel runtime。生成的实验代码与 Strudel 示例/第三方素材的许可应分别处理，不复制上游示例来训练模型或构成曲库。

## 接入前的具体变更

1. 权利人确认 AGPL 方案并核实已有代码、资产和依赖许可兼容。
2. 添加完整 AGPL 许可证、版权和第三方声明；设置 package.json 的 license 字段。
3. 通过独立 adapter 接入固定版本 runtime。页面提供许可与对应源码入口；发布记录包含可复现的源码版本和依赖锁文件。
4. 验收用户点击触发的播放、停止、A/B 切换和动态视觉反馈。已有 Studio 编辑、保存与导出流程继续独立可用。

若权利人不接受整个应用按兼容开源许可发布，则决策为不捆绑、不嵌入 runtime，使用导出代码和独立 Strudel 官方编辑器试听。

## 已核查的上游依据

- [Strudel 项目集成说明](https://strudel.cc/technical-manual/project-start/)：AGPL、集成应用兼容许可和网页发布源码要求。
- [Strudel FAQ](https://strudel.cc/learn/faq/)：程序与示例/曲目的许可边界。
- [GNU AGPL 第 13 节](https://www.gnu.org/licenses/agpl-3.0.html#section13)：修改版本与网络交互用户的对应源码提供要求。

本决策针对软件集成；没有把外部歌曲资料或录音认定为已取得再分发授权。
