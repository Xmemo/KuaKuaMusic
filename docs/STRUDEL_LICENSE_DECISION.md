# Strudel 集成许可决策

核查日期：2026-10-02。冻结 PRD 不变。

## 决策与落地

用户于 2026-10-02 要求协助确认并添加许可，本次采用 **AGPL-3.0-or-later** 作为项目自有软件的发布许可。根目录已添加完整 `LICENSE`、`NOTICE`、锁文件对应的 `THIRD_PARTY_NOTICES.md`，并设置 package.json 与锁文件的 license 字段。整个集成应用应提供与运行版本对应的完整源码入口，保留上游版权和许可声明、修改记录及依赖许可证。不能将 iframe 或动态加载视为当然免除许可义务的方案。

许可选择已经落地，本轮按用户要求已安装固定版本 Strudel runtime 并接入内置播放及动态可视化。core/mini/tonal/transpiler/draw 为 1.2.6，webaudio 为 1.3.0；保留上游实际版权与许可文本，发行包含对应源码链接、依赖锁文件和 BUNDLED_LICENSES.txt。许可证本身无需购买或申请密钥。锁文件中依赖均有许可字段，主要为 MIT、ISC、BSD 和 Apache-2.0；CC-BY-4.0 的依赖保留署名义务。许可字段核查不能证明已有图片或外部素材的权属：`public/*.png` 的制作/授权来源未在仓库中完整记录，公开分发前应补充；不把它们或外部歌曲资料自动认定为 AGPL 可再分发素材。生成的实验代码与 Strudel 示例/第三方素材的许可分别处理，不复制上游示例来训练模型或构成曲库。

## 接入前的具体变更

1. 已添加项目自有软件的 AGPL 许可与锁定依赖清单；公开发行前补齐图片及外部素材的权属记录。
2. 安装 Strudel 时保留其实际版本的完整版权与许可文本，补充第三方声明。
3. 通过独立 adapter 接入固定版本 runtime。页面提供许可与对应源码入口；发布记录包含可复现的源码版本和依赖锁文件。
4. 验收用户点击触发的播放、停止、A/B 切换和动态视觉反馈。已有 Studio 编辑、保存与导出流程继续独立可用。

若权利人不接受整个应用按兼容开源许可发布，则决策为不捆绑、不嵌入 runtime，使用导出代码和独立 Strudel 官方编辑器试听。
