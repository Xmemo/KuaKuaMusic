# MusicLearning2026 技术架构 v1.2

本版保留 [PRD v0.3 冻结基线](MUSICLEARNING2026_PRD_V0.3_FROZEN.md)、本机 Codex 执行方式和 GPT 6 Luna / xhigh 默认设置。它修复首轮分析的身份/范围隔离、四维覆盖、三种概括、分模块解释、补检与阶段进度。音频输入不在本轮范围；应用不会声称听取或测量歌曲。

## 首轮研究流程

1. 首轮最多 3 次搜索、读取 5 个来源页；服务端为读取材料登记片段并验证正文定位。
2. 草拟判断，不让草稿直接成为页面结论。事实、听感、解释、通用原理和未知分别标记。
3. 审核所选录音身份；逐条审核判断，并标记判断适用于录音、作品、来源所述版本或通用原理。
4. 计算文化、和声、律动、音色四个维度的证据覆盖。核心维度缺少歌曲专属资料、关键来源登记失败，或审核支持的音乐判断仍无法确认适用范围时，按相应缺口补检一轮，同样最多 3 次搜索、读取 5 个新来源页；复用已有资料，两轮累计最多 10 个独立来源。触发「至少两项机制解释」深度门槛时，只计和声、律动、音色、编曲、结构或制作等音乐类别；文化背景、传播史和发行资料不算音乐机制。
5. 新资料会与旧资料一并重新草拟和审核。作品层面或来源版本的可靠判断不会仅因录音版本未确认而丢弃；录音专属判断则要求精确录音已确认。
6. 只对最终保留的判断撰写整体概括和模块解释，再逐段检查文案。单段失败时只重写该段一次；仍失败时清空该段，不影响已通过文案。

分析状态按「覆盖」与「文案审核」共同确定：四个核心维度齐全且无文案失败为「完整」；至少一个维度有歌曲依据、但维度未齐或个别文案未通过为「部分完成」（即便四维都有资料，文案失败也可以是部分完成）；没有任何歌曲专属维度依据时为「资料不足」。

界面始终显示四个维度，状态为「已有解读」「听歌指导」或「资料不足」。通用听歌练习固定标注为通用内容，不作为歌曲分析覆盖。编曲、结构与制作可按资料增加。来源和理由默认折叠；明确的不确定性直接显示。研究 API 支持可选 SSE 阶段事件；不发送 `Accept: text/event-stream` 的调用仍获得普通 JSON。

## 判断及文字合同

`EvidenceClaim` 使用 `scope.level` 与 `scope.label` 标识适用范围，并以 `prerequisiteClaimIds` 记录解释的前提。来源版本判断按其证据片段 ID 找到已登记来源；引用来源须唯一确定同一 `versionScope`，服务端再将 `versionScope` 与显示标签规范为登记值。若证据来自多个不同来源范围，则保留为范围未确认。这样不会因模型改写范围标签而过滤已获支持的判断，也不会将不同版本的证据拼在一起。前提失效会沿依赖关系移除解释。身份字段由 `identityFields` 分别审核；例如年份失败只清除年份，专辑、作品背景和其他录音判断单独决定。

模块保留摘要的连贯自然语言，并以 `summaryClaimIds`、`explanationClaimIds` 和逐条听歌线索映射至审核后的判断。摘要不再要求逐字拼接判断原文。整体观感保留 `{text, claimIds}` 结构；走心从有依据的音乐对比/音色谈可能的听者感受，上头突出可回听的钩子或变化，懂行解释具体机制并简释术语，但共用同一组最终证据。模型输出的内部判断 ID 只保存在结构化引用中，页面文案不显示原始 ID。审核输入包括每段文字和引用的前提。

每个有歌曲资料的模块按「一句话特点、两段机制解释、2–3 条听歌线索、依据与限制」呈现。听歌线索逐条审核；失败只清空该条，其他通过的线索保留。若模块的合格线索少于两条，定向重写整个线索组一次，保留通过项并补充不同且具体的线索；最终仍少于两条时如实列入资料缺口并标为部分完成。精确录音线索必须引用所选录音范围的判断；若来源描述了一个可识别版本但该版本尚未映射到当前流媒体链接，线索可标为 `source_version`，必须引用同模块内来源版本判断，并以条件句提示“若当前播放录音与来源讨论的版本相同……”。页面须显示「来源版本听歌线索」，避免读者误以为已验证当前录音。通用线索必须标为 `general`，教具体的听辨方法，不得改写成歌曲事实，也不计作歌曲分析覆盖。文案复核按同一适用范围检查线索。

Schema 单一来源为 `music-learning/contracts.mjs`，生成物为 `schemas/*.schema.json`；TypeScript 类型定义位于 `music-learning/types.ts`。新研究记录使用 `schemaVersion: 1.2`；1.1 历史读取时只补显示默认字段，不改写原保存文件，旧深挖和 Studio 关联保留。重新研究创建独立快照。

## 边界

服务端仍自行读取公开来源、限制内容类型/大小/重定向并验证公开 IP。只有实际读取到的正文片段可登记；精确片段无法定位时，会用实际正文中的短句再匹配一次，失败就记录缺口并排除该片段。涉及作品、表演或录音版本的摘录应将附近的问题、标题或上下文一并纳入片段，避免失去适用范围。若审核发现受支持的音乐判断仍无法确认适用范围，或四维覆盖/关键来源登记有缺口，服务端只补检一轮；补检按具体缺口找关系/机制证据，复用已有资料并最多登记 10 个来源。来源登记失败保留失败原因。来源存在不自动证明语义结论正确，逐条语义与最终文案仍由模型审核，需人工复核。

Codex CLI 继续使用 `gpt-6-luna`、`xhigh` 默认值；本轮没有改变模型配置，也没有增加音频输入。模型接口、研究 API、来源边界与历史包约束详见上一版 [v1.1 技术架构](TECHNICAL_ARCHITECTURE_V1.1.md)。

研究子进程仅开放 MusicBrainz 的搜索、录音、发行和作品查询工具，避免向模型暴露与本任务无关的艺人目录、封面和批量枚举工具。单次资料检索超时上限为 12 分钟，草拟/审核/写作等单步为 6 分钟。页面会显示研究阶段并允许用户取消；超时按实际阶段报告，不保存半成品分析。

## 验收

自动回归覆盖：单条判断删除不重写其他概括；单段写作失败局部重试；身份字段独立降级；作品/录音/来源版本范围；解释前提失效；v1.1 历史只读兼容；JSON 与 SSE；研究取消、深挖追加、Studio 保存恢复。真实歌曲验收需分别检查 Queen《Bohemian Rhapsody》、DuDa、Kyrie 的输出是否满足冻结 PRD 与本轮分析目标，并在 Mac Chrome 检查桌面、切换行为和窄屏阅读。自动测试不代替真实资料质量验收。
